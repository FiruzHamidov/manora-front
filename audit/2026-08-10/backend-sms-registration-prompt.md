# Промпт для backend: регистрация и вход только по телефону и SMS

Репозиторий: `/Users/sarvat/Documents/GitHub/manora-backend` (Laravel).

Нужно добавить атомарный endpoint `POST /api/sms/register`, который завершает регистрацию по номеру телефона и SMS-коду без имени, email и пароля. Frontend уже отправляет:

```json
{
  "phone": "+992918555581",
  "code": "123456"
}
```

Требования:

1. Валидировать `phone` и шестизначный `code`; телефон нормализовать через существующий `PhoneNormalizer`/`SmsAuthService` точно так же, как `/sms/request` и `/sms/verify`.
2. Проверять код с purpose/scenario `registration`. Код должен быть одноразовым, иметь TTL и после успешной транзакции обязательно потребляться.
3. В одной DB-транзакции:
   - повторно проверить отсутствие пользователя с таким нормализованным телефоном;
   - создать активного пользователя с ролью `user` (fallback `client`, как в текущем `register`);
   - задать безопасное системное имя, например `Пользователь <последние 4 цифры>`;
   - установить `auth_method = sms`;
   - пароль не принимать от клиента; если колонка БД обязательная, записать криптографически случайный недоступный пароль через `Hash::make(Str::random(64))`;
   - сохранить текущую модель onboarding/auth state так, чтобы пользователь мог сразу пользоваться базовым личным кабинетом и позже заполнить профиль.
4. Вернуть тот же контракт, который уже использует успешный вход:

```json
{
  "token": "...",
  "user": { "role": {} },
  "auth_state": { "code": "..." }
}
```

Статус успешного создания — `201`.

5. Ошибки:
   - `422` — неверный формат телефона/кода;
   - `409` — аккаунт уже существует, с field error для `phone`;
   - `422` (или единый существующий статус SMS-проверки) — неверный/просроченный/уже использованный код;
   - `429` — лимит попыток; endpoint покрыть throttle.
6. Не менять контракты существующих `/api/sms/request`, `/api/sms/verify`, `/api/register` и password login.
7. Исключить race condition: два параллельных корректных запроса для одного телефона не должны создать двух пользователей (unique constraint + корректная обработка конфликта).

Добавить Feature-тесты:

- успешная регистрация создаёт одного активного SMS-пользователя, возвращает token/user/auth_state и потребляет код;
- повторное использование кода отклоняется;
- существующий телефон возвращает `409` и не меняет пользователя;
- неверный и просроченный код отклоняются;
- разные форматы одного таджикского номера нормализуются к одной записи;
- деактивированный существующий аккаунт не перезаписывается;
- параллельный/повторный запрос не создаёт дубль;
- старые auth-тесты остаются зелёными.

После реализации выполнить `composer test` и показать изменённые маршруты через `php artisan route:list --path=sms`.
