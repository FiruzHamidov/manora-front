В рабочем дереве могут находиться незавершённые изменения другого разработчика: не удаляй, не откатывай и не перезаписывай их. Перед изменениями изучи `PropertyController`, модель `Property`, текущие dictionary-контроллеры и policies, маршруты `api.php`, миграцию таблицы `properties` и существующие тесты справочников.

## Проблема

Поле `properties.document_type` сейчас валидируется фиксированным enum:

```text
ownership_certificate
technical_passport
sale_purchase_agreement
inheritance_certificate
other
none
```

Из-за этого администратор не может добавлять, переименовывать, упорядочивать или отключать типы документов через раздел «Справочники».

## Задача

Реализуй полноценный управляемый справочник типов документов недвижимости с публичным чтением и защищённым CRUD для администраторов. Сохрани строковое значение `document_type` в объявлениях и совместимость со всеми существующими записями и фильтрами.

## Модель данных

Добавь таблицу `property_document_types`:

```text
id          bigint primary key
slug        string unique
name        string
sort_order  unsigned integer default 0
is_active   boolean default true
created_at / updated_at
```

Заполни её существующими значениями в таком порядке:

1. `ownership_certificate` — `Свидетельство о собственности`
2. `technical_passport` — `Технический паспорт`
3. `sale_purchase_agreement` — `Договор купли-продажи`
4. `inheritance_certificate` — `Свидетельство о наследстве`
5. `other` — `Другой документ`
6. `none` — `Документы отсутствуют`

Миграция должна быть повторяемой и не менять существующие значения `properties.document_type`. Не заменяй строковую колонку на внешний ключ в рамках этой задачи: публичный контракт должен продолжать принимать и возвращать slug.

## API

Добавь ресурс:

```text
GET    /api/property-document-types
POST   /api/property-document-types
PUT    /api/property-document-types/{propertyDocumentType}
DELETE /api/property-document-types/{propertyDocumentType}
```

### Публичное чтение

`GET /api/property-document-types` доступен без авторизации и по умолчанию возвращает только активные элементы, отсортированные по `sort_order`, затем по `id`:

```json
[
  {
    "id": 1,
    "slug": "ownership_certificate",
    "name": "Свидетельство о собственности",
    "sort_order": 10,
    "is_active": true
  }
]
```

Для авторизованных `admin` и `superadmin` разреши параметр `include_inactive=1`, чтобы админка могла управлять отключёнными значениями.

### Управление

`POST`, `PUT`, `DELETE` доступны только активным `admin` и `superadmin`:

- без авторизации — `401`;
- остальные роли — `403`;
- `name`: required string max 255;
- `slug`: required, уникальный, формат `^[a-z0-9_]+$`;
- `sort_order`: nullable integer min 0;
- `is_active`: boolean.

Удаление должно быть безопасным:

- если slug уже используется в `properties.document_type`, физическое удаление запрещено с `409`; предложи отключить запись через `is_active=false`;
- если значение нигде не используется, допустимо удаление с текущим стандартным статусом проекта (`200` или `204`);
- изменение slug используемой записи также запрети с `409`, чтобы не сломать старые объявления;
- имя, порядок и активность можно менять независимо от использования.

## Интеграция с объявлениями

1. Замени фиксированный `in:...` в create/update недвижимости на проверку существующего активного slug из `property_document_types`.
2. Поле остаётся `nullable`.
3. При частичном обновлении отсутствие `document_type` не меняет сохранённое значение.
4. Старое объявление с ныне отключённым значением должно продолжать открываться и сериализоваться.
5. Новое объявление нельзя создать с отключённым или неизвестным slug — `422` с ошибкой `document_type`.
6. Фильтрация по `document_type` продолжает принимать slug и не меняет контракт.

## Тесты

Добавь feature-тесты:

1. Миграция/сидер создаёт все шесть текущих значений без дублей.
2. Публичный index возвращает только активные записи в правильном порядке.
3. Admin/superadmin видят неактивные с `include_inactive=1` и могут создавать/редактировать записи.
4. Другие роли получают `403`, гость — `401` на изменяющих маршрутах.
5. Дубликат slug и неправильный формат возвращают `422`.
6. Нельзя удалить или изменить slug используемого типа — `409`.
7. Неиспользуемый тип удаляется.
8. Создание недвижимости принимает активный slug и отклоняет неизвестный/неактивный.
9. Старое объявление с отключённым типом продолжает возвращаться в show/index.
10. Существующая фильтрация объявлений по `document_type` не ломается.
