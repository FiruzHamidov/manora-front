# Полный аудит manora.tj — 10.08.2026

## Охват

Проверены production desktop и mobile, публичный каталог, новостройки, транспорт, ипотека, новости, партнёры, авторизация по паролю, профиль и ключевые admin-разделы. Изменяющие действия на production (создание, редактирование, удаление, модерация) не выполнялись. Дополнительно проверены frontend и backend код, маршруты и тесты.

Автотесты на момент аудита:

- frontend: lint, Node tests и production build проходят;
- backend: 134 теста, 862 assertions — проходят.

## Итог

Сайт в целом доступен, авторизация работает, основные страницы открываются. Подтверждены четыре значимых frontend-дефекта, один обязательный backend-контракт для упрощённой регистрации и несколько UX/accessibility замечаний.

## Найденные проблемы

### P0 — упрощённая регистрация frontend не совместима с текущим backend

Frontend после подтверждения регистрационного SMS вызывает `POST /sms/register`, но в backend есть только `/sms/request`, `/sms/verify` и старый `/register` с обязательными именем и паролем. Если выкатить frontend отдельно, завершение регистрации будет получать `404`.

- Слой: backend-контракт и порядок деплоя.
- Исправление: реализовать endpoint по промпту `backend-sms-registration-prompt.md`, затем выкатывать frontend.
- Статус: backend не изменялся; подготовлен отдельный промпт.

### P1 — просмотр/редактирование первых двух новостроек в админке не работает

Шаги: войти администратором → `/admin/new-buildings` → нажать «Просмотр» у «Зарафшон» или «Навои Плаза».

Факт: переход на `/admin/new-buildings/24` или `/22`; просмотр показывает «Не найдено», редактирование показывает пустой wizard. Локальная запись `/admin/new-buildings/1` работает.

Причина: таблица брала объединённый публичный feed (local + Aura), а действия вызывали локальный management API. Aura ID не существуют в локальной БД. Это не проблема авторизации и не требует изменения backend.

- Слой: frontend.
- Исправление: admin-таблица переведена на защищённый `/manage/new-buildings` и больше не получает Aura-записи.
- Регрессия: добавлен тест `admin-new-buildings-management.test.mjs`.

### P1 — «Вторичка», «Коммерческая», «Аренда» и категории каталога дают пустой результат

Production-ссылки отправляют `sort=listing_type`, тогда как feed API принимает только `created_at` и `price`. Оба запроса `/api/feed/properties` и `/stats` отвечают `422`, но UI маскирует ошибку пустым состоянием.

- Слой: frontend/backend contract; backend валидирует корректно.
- Исправление: все дефолтные ссылки и каталог переведены на `sort=created_at`.
- Регрессия: добавлен contract-тест.

### P1 — глобальный loader блокирует главную до ~16 секунд

DOM и часть контента уже готовы, но fullscreen overlay «Загружаем главную…» остаётся более 6 секунд и исчезает примерно к 16-й секунде. Причина — overlay ждёт одновременно новостройки, недвижимость и автомобили, включая внешние feed-запросы.

- Слой: frontend UX/performance.
- Исправление: убран блокирующий fullscreen loader; секции могут загружаться независимо.
- Регрессия: тест запрещает возвращение блокирующего overlay.

### P2 — Aura-карточки показывают ложную информацию о застройщике и звонке

При отсутствии данных показывались «Неизвестно» со значком верификации и ссылка `/developers/0`; кнопка «Позвонить» вела на страницу объекта, а не на телефон.

- Слой: frontend/data presentation.
- Исправление: неизвестный застройщик больше не получает ссылку/verification badge; при отсутствии телефона показывается «Подробнее».

### P2 — ошибки загрузки detail/edit новостройки не объясняются пользователю

Просмотр показывает только «Не найдено», а edit при неуспешном запросе оставляет заголовок и шаги без формы и без сообщения/повторной попытки. Основной триггер устранён фильтрацией admin-коллекции, но компонентам detail/edit всё равно нужен явный error state.

- Слой: frontend resilience.
- Исправление: добавлено явное состояние `404`/ошибки с объяснением, кнопкой повторного запроса и возвратом к списку.
- Статус: исправлено на frontend.

### P2 — пустой каталог транспорта не помогает продолжить сценарий

При отсутствии машин отображается «Объявления по заданному фильтру не найдены», даже когда пользователь не задавал фильтры. Нет CTA «Добавить объявление» или «Сбросить фильтры».

- Слой: frontend UX.
- Исправление: добавлено отдельное пустое состояние. При активных фильтрах доступен их сброс, без фильтров — настройка поиска и возврат на главную.
- Статус: исправлено на frontend.

### P2 — login modal не имел dialog semantics

В accessibility tree окно входа не определялось как dialog.

- Слой: frontend accessibility.
- Исправление: добавлены `role="dialog"`, `aria-modal="true"`, доступное имя.

### P3 — мобильная admin-таблица требует горизонтального скролла

На ширине 390 px видна только часть таблицы и действия находятся за пределами первого экрана. Технически таблица прокручивается, но для мобильной админки удобнее карточки строк или фиксированная колонка действий.

- Слой: responsive UX.
- Исправление: на мобильных таблица заменена карточками с основными данными и доступными действиями; desktop-таблица сохранена.
- Статус: исправлено на frontend.
