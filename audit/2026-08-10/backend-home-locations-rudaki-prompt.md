# Промпт для бэкенда: добавить Рудаки в справочник городов/локаций

Нужно обеспечить поддержку выбора Рудаки в фильтре объявлений на главной странице Manora.

## Текущее поведение

`GET /locations` возвращает Душанбе, Худжанд, Бохтар, Вахдат, Гиссар и другие локации, но не возвращает Рудаки. Поэтому фронтенд не может показать Рудаки как рабочий вариант: без реального `location_id` выбор не сможет фильтровать объявления.

## Требуемое изменение

1. Добавить в справочник `/locations` отдельную активную запись с каноническим названием `Рудаки`.
2. Вернуть для записи стабильный числовой `id`, который принимается фильтром `GET /properties?location_id={id}`.
3. Если Рудаки уже хранится под другим написанием (`Рӯдакӣ`, `Рудакӣ` или как район), нормализовать публичное русское название до `Рудаки`, не создавая дубль.
4. Не менять существующие `id` других локаций.
5. Убедиться, что объявления с этой локацией действительно возвращаются при фильтрации по её `location_id`.

## Формат ответа

Пример элемента в `GET /locations`:

```json
{
  "id": 123,
  "city": "Рудаки",
  "district": null
}
```

Допустимо поле `name` вместо `city`, если это соответствует текущему контракту, но структура должна оставаться совместимой с остальными элементами `/locations`.

## Проверки

- `GET /locations` содержит ровно одну каноническую запись `Рудаки`.
- Поиск/сериализация ответа работает в UTF-8.
- `GET /properties?location_id={rudaki_id}` возвращает только объявления выбранной локации.
- Существующие фильтры Душанбе, Худжанд, Бохтар, Вахдат и Хисор/Гиссар не ломаются.
