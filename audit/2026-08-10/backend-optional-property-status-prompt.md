# Промпт для бэкенда: сделать тип объекта недвижимости необязательным

Работай только в репозитории `/Users/sarvat/Documents/GitHub/manora-backend`. В рабочем дереве могут быть незавершённые изменения другого разработчика: не удаляй и не откатывай их. Перед изменениями найди текущие Form Request/DTO, контроллеры, сервисы, модель и миграции, отвечающие за создание и обновление недвижимости.

## Задача

Поле `status_id`, которое в текущем API используется как «Тип объекта» (Панельный, Кирпичный, Монолитный, Блочный, Деревянный), больше не показывается пользователю при добавлении объявления. Сделай это поле необязательным в backend API.

## Требования

1. В endpoint создания недвижимости разреши запрос без `status_id` и с `status_id: null`.
2. В endpoint обновления недвижимости:
   - отсутствие `status_id` не должно изменять сохранённое значение;
   - явный `status_id: null` должен очищать значение, если текущий контракт обновления поддерживает очистку nullable-полей.
3. Валидация должна быть вида `nullable|exists:...`, а не `required`. Используй фактическую таблицу справочника из проекта.
4. Колонка в БД должна допускать `NULL`. Если сейчас стоит `NOT NULL`, добавь отдельную безопасную миграцию изменения колонки. Не подставляй первый элемент справочника и не создавай фиктивное значение по умолчанию.
5. Модель, DTO/ресурс и сервисный слой должны корректно работать с `null`.
6. Ответы create/show/update должны возвращать `status_id: null` (и `status: null`, если relation включён в ресурс), не вызывая ошибку сериализации.
7. Старые объявления с заполненным `status_id` и фильтрация по этому полю должны продолжать работать без изменений.
8. Не меняй значение или назначение других полей недвижимости.

## Ожидаемые статусы

- создание без `status_id` — успешный текущий статус create (`200` или `201` по существующему контракту);
- обновление без `status_id` — успешный текущий статус update;
- неизвестный ненулевой `status_id` — `422` с ошибкой поля `status_id`;
- просмотр объекта с `status_id = null` — `200`.

## Обязательные тесты

Добавь feature-тесты:

1. Создание недвижимости без `status_id` успешно и сохраняет `NULL`.
2. Создание с `status_id: null` успешно.
3. Создание с существующим `status_id` по-прежнему успешно.
4. Несуществующий ненулевой `status_id` возвращает `422`.
5. Частичное обновление без поля сохраняет прежний `status_id`.
6. Явный `null` очищает поле, если это соответствует принятой PATCH/PUT-семантике проекта.
7. Show/index корректно сериализуют объявление без типа объекта.
